# 粘贴项目地址，先看已有公开报告

日期：2026-09-13（北京时间）。承接既有“GitHub / 首页 → 公开报告 → 首次价值”实验；9 月 16 日检查点不重置。

## 问题和假设

目标用户是已选定一个公开 GitHub、npm 或 PyPI 项目，想在采用前理解其证据和风险的开发者。首页有通用示例，但其项目地址表单直接提交到受保护的 `/evaluate`；即使相同项目已有公开报告，也会先出现登录要求。搜索页原本只按名称、描述和标签检索，不能可靠按来源地址找到已有项目。

03:21 生产基线：D7 页面浏览 18，评测 CTA 2，搜索 / GitHub / 社区来源各 0，新增用户 0、首次完成评测用户 0；189 个项目中 178 个已有报告。记录是聚合次数，不是独立访客；没有证据能量化登录门槛造成多少流失。用户此前确认“报告可以看懂”，因此本轮处理获得报告的路径，不继续重写报告或扩写指南。

假设：访客粘贴自己的候选项目后，先找到对应的存量公开报告，可以在登录前获得与任务相关的价值；需要新评测时再继续登录。增加库存或代码本身不算假设得到验证。

## 交付契约

- 首页 GET 表单改为 `/search?source=...`，按钮明确为“查找报告”。普通关键词搜索保留 `q`，避免把 `react` 这样的关键词强制理解为某个 npm 包。
- 来源匹配只查询数据库中的 active 项目，使用参数化、带边界的注册表匹配。保留 GitHub owner、npm scope、PyPI 名称等价规则，不能以易碰撞的 slug 或相同展示名称作为身份。
- 已有报告提供免登录直达报告锚点；已收录无报告单独说明；无匹配时保留经过校验的地址到 `/evaluate` 及登录返回路径，不自动排队或抓取外部地址。
- 显示历史报告范围限制：仓库级匹配不意味着粘贴的分支、文件或特定版本已接受评测。没有安全认证承诺，没有重评或积分消耗。
- 支持无 JavaScript 的原生 GET 表单。非法、重复、超过 500 字的 source 参数不得变成全量查询；含凭证的地址不回填输入框或后续链接。
- 查询页继续 noindex、canonical `/search`。不增加公共 API、依赖、schema、登录豁免或模型调用。

## 观察和停止条件

在原有 9 月 16 日检查点查看搜索页、目标报告访问与后续评测意图；页面阅读本身可能已完成用户任务，不要求注册才算有价值。现有匿名聚合无法把一次查找与某个报告 / 账户逐人关联，不能计算精确漏斗或声称归因。

首页查找动作从此不再计作 `evaluation_cta_click`，因为没有开始新评测；用户点击后续评测链接仍按现有逻辑统计。因此发布前后全站 CTA 不可直接当作同口径转化率比较。无新 Cookie / 访客标识，也不记录输入项目名。

9 月 16 日若仍无真实目标访问，停止继续优化此入口，优先推进已准备的单项合规目录分发，不扩同类页面。若实际用户找不到已收录项目，记录公开输入与期望项目，补充身份匹配回归；若读到报告但不能形成决定，再处理对应证据问题。无需等观察窗口来修正可复现错误。

## 验证方法

本地：`npm run typecheck`、`npm run lint`、`npm run test:evaluation`、`npm run build`。来源回归加入现有 `tests/skill-source-identity.test.ts`，随默认网站测试执行。

数据库：`node --import tsx --test tests/source-search-postgres.test.ts`。使用只读事务和 CTE 合成行遮蔽业务表，验证三种注册表、同名异源、前后缀碰撞、归档 / 移除、无匹配与非法输入；不访问业务行，不写入临时或持久表。

浏览器：`PLAYWRIGHT_MODULE=/path/to/existing/playwright SOURCE_SEARCH_URL=http://127.0.0.1:PORT node scripts/check-source-search.mjs`，以及更新后的 `scripts/check-home-layout.mjs`。检查真实匿名流程、登录地址保留、无 JS 降级、320/390/768/1280 布局及 canonical；所有非 GET/HEAD 和统计请求均拦截，不制造注册、流量事件或评测任务。

本地测试运行器初次被沙箱禁止建立 IPC 管道，测试尚未启动；在允许本机 IPC 的执行环境中运行原命令后通过。未跳过业务断言。生产候选和最终上线结果在完成后追加。
