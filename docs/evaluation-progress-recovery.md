## 根因与基线

15:39 只读核对线上健康、安全及同日数据：183 个 Skill、172 个已评测项目、191 份历史报告；D1 用户评测仍为 0，未观察到真实用户故障。延续上一轮报告复评入口的链路检查，在 `EvaluationWorkbench` 发现所有非 401 查询错误都无限重试，且 fetch 没有超时；任务处于 active 状态时提交按钮被锁定，没有解释或恢复入口。

以真实组件、本次构建 CSS、隔离 Chromium 和模拟 API 复现：404 持续返回时，8.5 秒内自动发起 3 次 GET，界面无恢复提示，提交按钮持续禁用。这是故障注入基线，不是线上用户失败统计。

## 本轮实现

- 每次进度 GET 包括读取响应体最多 15 秒；网络、5xx、无效 JSON、错误任务 ID、非法状态/进度连续失败 3 次后暂停查询，重试间隔 3.5/7 秒。有效响应重置连续失败计数，正常 pending/running 保留原查询频率。
- 403/404/429 立即暂停，401 停止并转登录后账户页查原任务；仅服务端明确 `failed` 才显示评测失败。查询异常不伪造任务失败、进度、成功或额度变化，不展示原始错误。
- 页面解释“只暂停此页面的查询，后台任务可能仍在执行”，保留最后确认的进度，提供“继续查询原任务”和“查看账户任务”。继续查询只发 GET，不重新 POST、不清空原任务、不扣额度。
- 完成/失败停止定时器；组件卸载取消在途请求与定时器，并忽略晚到响应。只接收经过基本校验的进度字段，不把任意响应对象合并进页面状态。
- 无评分、Worker、身份认证、注册、额度、数据库、锁文件或依赖更改；不取消后台任务。未配置的注册保护仍不在本轮发布范围。
