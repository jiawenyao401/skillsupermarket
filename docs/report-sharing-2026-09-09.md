# 公开报告分享入口 · 2026-09-09

## 用户反馈与本轮范围

负责人反馈“报告可以看懂，继续吧”。据此接受其可读性反馈，不再把招募五人试用当作继续交付的前置条件；这不是五名独立用户测试通过，也不是已有自然获客。试用材料保留为可选工具。

本轮只解决一个实际入口缺口：报告页已有面向项目作者的 README 徽章，但普通读者需要手动从地址栏找链接，且可能带着无关查询参数。假设：在公开报告上提供直接复制入口，便于读者将证据发给一起选型的同事。**入口交付不等于用户真的分享或产生增长。**

## 行为契约

- 只在已有报告的公开 Skill 详情页显示；账户/评测工作台没有传入分享地址时不显示，不把私人任务变成公开链接。
- 地址由服务端 canonical + `#evaluation-report-title` 组成；不读当前地址、Cookie、账号、私有查询或剪贴板内容。
- 点击后才请求写入链接；Promise 成功后才显示已复制。等待时禁止重复点击，失败/不支持时展开手动复制框并聚焦选中。
- 原生 details 和只读文本框让禁用 JavaScript 时仍能取到链接。没有系统分享弹窗、第三方 SDK、后台代发或新网络请求。
- 明确收件人可免登录阅读，链接显示最新报告而非固定版本存档。沿用已有报告日期、规则版本、限制说明和 OG 预览，不把链接冒充安全认证。
- 不新增账户、数据库字段、评分规则、额度、追踪标识或依赖。保留原 README 徽章功能。

遵循本机 Next.js 16.3 的 Server/Client Components 与 use-client 指南：详情和报告仍在服务端，只把复制操作做成小型客户端组件。剪贴板成功/拒绝行为核对了 [MDN writeText 文档](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)，不绕过浏览器权限。

## 验证方法与边界

单元回归检查服务端 canonical 构造、恶意 slug 编码、无查询参数、手动降级、提示语和未指定公开链接时不显示。浏览器脚本：

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/existing/playwright node scripts/check-report-share.mjs
```

可用 `REPORT_SHARE_URL` 指定已有的本机回环预览。脚本拦截所有非 GET/HEAD 和统计请求，剪贴板写入仅截获到浏览器内存，不读写操作者的系统剪贴板、不注册或创建评测。

覆盖 320/375/390/414/768/1024/1280 七档屏宽，两份存量报告、键盘复制、长链接、拒绝/不支持/等待状态、禁用 JavaScript 降级和匿名接收方阅读。静态页面快照 + 新组件真实 hydration 仅验证组件，不代替完整 Next.js 运行和生产验收。
