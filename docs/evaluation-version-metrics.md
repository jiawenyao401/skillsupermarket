# 评测版本覆盖与产出统计

## 要解决的问题

2026-09-08 北京时间 00:37，183 个有效 Skill 中 172 个有报告，覆盖率 94.0%；但只有 1 个最新报告使用当前算法 3.12.0，其余 171 个仍是其他版本。发布后的唯一任务是运营冒烟，没有新算法的真实用户样本。原报表无法展示这种区别，容易把库存报告覆盖与算法上线验收混为一谈。

新增后台“评测版本覆盖”表，以及 `npm run growth:report -- --json` 的 `evaluatorRollout` 字段。两者复用同一 SQL 和汇总函数；新增 1 次只读聚合查询，实测单次 23.1ms，仅作样本，不是 SLA。无迁移、无新依赖、无评分/队列/额度变更，也不会触发重评或模型调用。

## 数据契约

- 仅统计当前状态为 active 的 Skill 的报告。
- `latestReports`：按 Skill 去重，优先取评测时间最新者；相同时间用 ID 降序，空时间排最后。
- `currentVersionLatestReports`：最新报告版本与当前代码的 `EVALUATOR_VERSION` **精确相等**，不从部署时间或其他字段猜版本。
- `currentVersionCoverage`：当前版本最新报告数 / active Skill 数，单位为百分数；空库存为 `null`，有库存但未采用为 `0`。不是“准确率”，也不表示已有报告已全部更新。
- `otherVersionLatestReports`：其他已知版本；不称作过期，因为回滚后其他版本可能更高。
- `unversionedLatestReports`：缺失、非字符串或不符合本站三段数字版本格式的元数据合并为未知，不输出任意原始字符串。
- `versions[].reports1d/7d/30d`：按 `evaluated_at` 滚动 1/7/30 天统计所有报告产出，包含被后续重评替代的历史报告；下界包含、未来时间不计入。不要将它误读为最新报告库存或用户数。
- `reportSourceAttributionAvailable: false`：目前报告没有直接关联任务 ID，不能用相近时间或相同 Skill 猜测归属。这些产出包含用户、运营、重评和发布冒烟，不代表用户增长。
- 表格只在现有超级管理员鉴权成功后查询，不新增公开接口或客户端数据库访问。组件不增加客户端 JavaScript。
