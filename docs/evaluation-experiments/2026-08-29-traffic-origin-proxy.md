# 反向代理同源判断回归（2026-08-29）

## 基线

- Nginx 日志中最近 17 次 `/api/events` 请求均来自非自动化浏览器，状态码全部为 `204`。
- `traffic_daily` 没有对应聚合记录，导致页面浏览和评测 CTA 指标始终为 0。
- 事件路由只比较浏览器 `Origin` 与 Next.js 运行时 `request.url`。反向代理场景下，后者可能是内部 HTTP 地址，因此会误拒绝正式站的合法同源事件。

## 假设与改动

除运行时请求地址外，将经过统一规范化的 `NEXT_PUBLIC_SITE_URL` 也作为允许的正式站来源；继续保留 `Sec-Fetch-Site`、自动化客户端过滤、路径白名单和限流，不放宽跨站请求边界。

## 验证与停止条件

- 固定回归覆盖正式站经内部代理、直接本地访问、缺失/opaque/非法/外站来源。
- 部署后观察首个真实浏览器事件应返回 `202` 并形成聚合记录；不制造测试访问量污染真实指标。
- 若仍持续出现非自动化浏览器 `204`，停止扩展来源白名单，改为增加脱敏拒绝原因计数后继续定位。

## 次日增量结论

- 部署后新出现的 17 次事件仍全部返回 `204`，公开来源主机均为 `www.skillsupermarket.com`。
- 根因不是新的外站流量，而是 Nginx 同时承载主域和 `www`，旧逻辑仅允许 canonical 主域，并拒绝浏览器对两个同站域名产生的 `same-site` 元数据。
- 修复同时增加 `www` 显式来源白名单与永久主域重定向；`cross-site`、未知 Fetch Metadata 和非白名单 Origin 继续失败关闭。
